# Задание 4

## Анализ: какие логи, из каких систем и на каких уровнях

**Какие системы должны логировать:**

1. Shop API
2. CRM API
3. MES API
4. Messages Queue (RabbitMQ — через плагины/логгирование брокера)
5. 3D File Storage (S3-based) — ошибки при загрузке/доступе
6. Internet Shop / CRM / MES UI — client-side логгирование (ограниченно)

**Список логов уровня INFO:**

| Событие                                     | Что логируем                                           | Уровень |
|---------------------------------------------|--------------------------------------------------------|---------|
| Заказ создан                                | Время, order_id, user_id, source system                | INFO    |
| Изменение статуса заказа                    | order_id, старый статус, новый статус, user_id, system | INFO    |
| Загрузка 3D модели                          | order_id, user_id, имя файла, размер                   | INFO    |
| Расчёт стоимости заказа                     | order_id, стоимость, время расчёта                     | INFO    |
| Передача заказа в RabbitMQ                  | order_id, тема очереди                                 | INFO    |
| Подтверждение от оператора                  | operator_id, order_id, комментарий                     | INFO    |
| Ошибка обращения к базе данных              | запрос, код ошибки                                     | ERROR   |
| Попытка доступа к неавторизованной операции | user_id, путь запроса, IP                              | WARN    |
| Превышение времени отклика API              | endpoint, latency, trace_id                            | WARN    |
| Ошибки загрузки 3D файла                    | user_id, имя файла, код ошибки                         | ERROR   |

## Мотивация

Что даёт логирование:

1. Уменьшение времени разбора инцидентов
2. Быстрое выявление нестабильных зон (частые ошибки)
3. Улучшение качества релизов (через анализ логов)
4. Снижение нагрузки на поддержку (лог всё скажет)

**Приоритетные системы для логирования и трейсинга:**

| Система               | Приоритет логирования      | Приоритет трейсинга | Почему                           |
|-----------------------|----------------------------|---------------------|----------------------------------|
| Shop API              | Обязательно                | Обязательно         | Ключевой вход в систему          |
| CRM API               | Обязательно                | Обязательно         | Изменение заказов, подтверждение |
| MES API               | Обязательно                | Обязательно         | Производственная логика          |
| Messages Queue        | Логирование ошибок         | Обязательно         | Потеря сообщений критично        |
| UI-сервисы (CRM, MES) | Только основные события    | Нет                 | Клиентский уровень не трейсится  |

## Предлагаемое решение

**Выбор технологии:** Logstash + Elasticsearch + Kibana (ELK Stack)

**Что потребуется:**

1. Добавить логгеры (Logback, Serilog, NLog и т.п.) в API
2. Установить агенты (Filebeat, Fluent Bit) на хосты с сервисами
3. Настроить централизованный сбор и фильтрацию логов
4. Создать индекс в Elasticsearch
5. Добавить визуализацию и фильтры в Kibana

**Безопасность логов:**

1. Удаление/маскирование чувствительных данных
2. Доступ к Kibana только для авторизованных сотрудников (SSO/LDAP)
3. Шифрование логов в хранении и передаче

**Хранение логов**

1. Хранение: 14 дней (для INFO), 30 дней (для ERROR)
2. Создание отдельных индексов по системе: shop-api-logs, crm-api-logs и т.д.
3. Ротация: на уровне Logstash или index lifecycle policy

## Система анализа логов: что добавить

**Алерты:**

- Повышенное количество ошибок ERROR на endpoint
- Ошибки в подключении к БД
- Аномальное поведение (всплеск заказов)

**Аномалии:**

- Резкий рост заказов (10 000 в секунду)
- Ошибки определённого типа, превышающие порог

**Фильтрация по trace_id**

- связка логирования и трейсинга
