# Задание 3

## Анализ системы и точек для трейсинга

На основе C4-диаграммы, а также описания бизнес-процессов, ключевые зоны, где заказ может "сломаться" или зависнуть, находятся:

1. Internet Shop -> Shop API. Потеря запроса от клиента, некорректная передача данных 3D-модели.
2. CRM API -> Messages Queue. Потеря или дублирование сообщения.
3. Messages Queue -> MES API. Потеря сообщения или отсутствие обработки.
4. MES API -> MES. Долгая или неправильная обработка заказа оператором.
5. MES API -> 3d files storage. Ошибки при расчёте стоимости — если нет файла или он повреждён.

## Список данных для трейсинга

- trace_id — сквозной идентификатор запроса
- span_id — подэтапы внутри одного запроса
- временные метки входа и выхода из каждого сервиса
- статус выполнения запроса (успешно/ошибка)
- название операции (e.g. OrderSubmitted, OrderStatusUpdated)
- ключевые параметры: order_id, user_id, status, source system

## Мотивация

Ниже представлены выгоды, которые получит компания при внедрении метрик.

**Технические метрики:**

1. Время обработки заказа от создания до отправки (end-to-end latency)
2. Поиск "зависших" заказов (дольше обычного на определённом шаге)
3. Быстрая диагностика и устранение ошибок (видно, на каком шаге упал процесс)
4. Уменьшение случаев повторной отправки сообщений/заявок

**Бизнес-метрики:**

1. Снижение времени реакции на жалобы клиентов
2. Улучшение SLA с B2B-партнёрами (API-пользователями)
3. Снижение потерь от потерянных заказов/контрактов

## Предлагаемое решение

**Выбранная технология:**

- OpenTelemetry + Jaeger
- Сквозной трейсинг с использованием trace_id во всех API

**Компоненты и доработки:**

1. Shop API / CRM API / MES API. Интеграция OpenTelemetry SDK.
2. RabbitMQ. Прокидывание trace_id в заголовках сообщений.
3. Общая инфраструктура. Развёртывание Jaeger.
4. CI/CD. Настроить логгирование трейсов в окружениях.

## Компромиссы

1. Нет поддержки трассировки в старых библиотеках. В MES (C#) может потребоваться доработка библиотеки очередей.
2. Неизолированные инциденты. Ошибка вне бизнес-логики (например, потеря 3D файла, который был вручную удален).
3. Высокая стоимость хранения трейсов. При большом потоке заказов нужно ограничивать retention (например, 7 дней).

## Безопасность и доступ

1. Аутентификация по SSO (например, через Keycloak) для доступа к системе трейсинга
2. Доступ только для ролей: Поддержка, DevOps, Разработчики
3. Шифрование трафика между компонентами (TLS)
4. Аудит-доступа: логирование обращений к системе трейсов
