# Задание 1

## Идентификация проблем

1. Длительное время расчета стоимости в MES. Это приводит к задержкам и может вызывать тайм-ауты API.
2. Замедленная работа дашборда. Фильтрация и пагинация не помогла. Операторы не видят свежие заказы.
3. Линейный рост нагрузки на систему.
4. Потеря заказов. Клиенты не получают услуги вовремя, менеджеры не в курсе статуса заказа, крупные контракты срываются.
5. Ручное тестирование вызывает задержки релизов.

## Инициативы по улучшению

1. Оптимизация расчёта стоимости в MES
   - Использовать кеширование для одинаковых моделей.
2. Масштабирование инфраструктуры.
   - Добавить дополнительные инстансы для MES и CRM.
   - Использовать базу данных с репликами для разгрузки чтения.
3. Повышение надёжности передачи заказов.
   - Улучшить мониторинг очередей RabbitMQ.
   - Внедрить повторную отправку сообщений при сбоях.
   - Добавить логирование для анализа проблем.
4. Ускорение работы MES
   - Реализация кэширования дашборда
   - Оптимизация SQL-запросов для списка заказов
5. Автоматизация тестирования
6. Расширение команды
   - Найм дополнительного разработчика на C# для оптимизации MES.
   - Найм инженера по автоматизации тестирования для ускорения QA-процессов.

## Приоритетные инициативы

1. Оптимизация расчёта стоимости в MES. Это основная точка задержки в процессе заказа.
2. Повышение надёжности передачи заказов. Меньше потерянных заказов - больше довольных клиентов и отсутствие потерянных контрактов.
3. Автоматизация тестирования. Позволит выпускать релизы и исправления быстрее.

## Целевая архитектура через 6 месяцев

1. API работает на масштабируемых инстансах с балансировкой нагрузки.
2. Очереди сообщений устойчивы к высокой нагрузке.
3. MES отображает заказы моментально благодаря кэшированию.
4. Централизованный мониторинг помогает оперативно выявлять проблемы.
5. Тестирование автоматизировано, релизы выходят быстрее и без долгих задержек.
